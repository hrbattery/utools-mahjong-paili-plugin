# 手牌实验室 / fast-tenhou-paili

uTools 8 快速原型：截图导入 → 在线识牌 → 牌图/天凤牌串校正 → 本地数学进张分析。

## 运行

```sh
npm ci
npm test
npm run test:ui
npm run dev
```

`src/paili_engine.wasm` 已包含编译好的计算引擎，构建时内联到脚本以支持 uTools 的本地文件协议。普通前端开发不需要安装 Rust。

在 uTools「开发者工具」中新建本地插件，选择 `dist/plugin.json`，运行后搜索「牌理」。图片可从 uTools 主输入框粘贴进入，也可在插件内选图、粘贴、拖入或框选截图。此原型按 uTools 8 API 开发。

浏览器预览支持图片裁剪、文本/点选校正和完整本地计算。在线识牌和系统截图需要 uTools 宿主；浏览器不会伪造识别结果。模型下拉框只列出 `allAiModels()` 标记 `vision` 的模型。识别会消耗所选通道的额度，只有点击识别时才发送当前预览图片。

## 输入与计算约定

- 待切牌支持 `2/5/8/11/14` 张；待摸牌支持 `1/4/7/10/13` 张。
- 天凤牌串：`m` 万、`p` 筒、`s` 索、`z` 字，`1z–7z` 为东南西北白发中；`0m/0p/0s` 表示赤五。文本与点选编辑双向同步。空格和大写花色可接受。
- 只计算普通形、七对子、国士无双的向听数和降低向听数的有效进张，不计算收益、役、得分、振听、防守或同向听改良牌。
- 短手牌假定缺少的面子已固定；无需补齐即可算。已知吃碰杠可另填，例如 `123m 555p 7777z`。杠占一组面子、扣除四张牌；不区分明杠暗杠的得分语义。
- 未提供副露时只按手牌扣减，界面明确提示缺失组数；不是实际牌山剩余枚数。最多每种四张，红五与普通五合并计算。
- 采用 shanten-dp 的“可用牌约束”数学口径：输入已知副露后，不把已耗尽的牌视为未来可获得牌。该口径可能与平台对形式听牌的规则不同。
- 所有切牌候选均列出，先按切后向听数升序，再按进张枚数降序。赤五与普通五保持独立可选，但数学结果相同。
- 点击切牌，再点击有效牌可继续推演，支持撤销。模拟弃牌持续从可用牌中扣除。手动编辑、改副露或应用新识别会开始新分析。
- “天凤查看”仅传递当前手牌，不传副露、推演弃牌或可用牌约束；外部结果可能因此不同。
- 模型返回看不清的牌时保留 `?` 位置；所有牌位校正前不展示计算结果。输入非法时清除旧分析，防止误用。

## 复用边界

复用 tomohxx 的 **shanten-dp 0.3.2（MIT）**，保留版本锁与许可。自写标量 WebAssembly 桥接层，前端无服务器计算依赖。`pairi` 仓库在检视的提交 `6da8b46bc8b68fa936985dfb6f9bdce604c211e7` 未见许可证文件，因此没有复制其页面组件或图片资源。牌面使用本项目的文字/CSS 绘制。

来源与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

重新编译计算引擎需要 Rust（含 `wasm32-unknown-unknown` target）：

```sh
rustup target add wasm32-unknown-unknown
npm run build:engine
```

## 样本与验收

已准备 10 张天凤素材合成手牌、5 张公开雀魂对局图及其手牌裁剪，见 [samples/README.md](samples/README.md)。图片和标签保存在 `samples/private/`，可用 `npm run samples:tenhou`、`npm run samples:majsoul` 重新生成或下载。真实来源、标签与裁剪坐标保存在 `samples/majsoul-sources.json`；合成牌串保存在 `samples/tenhou-cases.json`。`samples/manifest.example.json` 用于继续标注自己的截图。

`npm test` 运行计算与解析测试；`npm run test:ui` 先构建，再使用 DOM 环境运行生产脚本，检查文本/点选同步、推演撤销和识别请求竞态。后者模拟 uTools 接口与图片解码，不等同于浏览器视觉验收或实际宿主调用。

样本已完成本地生成、裁剪和初步目视标注；浏览器界面经过交互与显示检查。uTools 导入运行、系统截图权限及真实模型识别仍需实测，不能用合成样本、算法测试或模拟接口测试替代真实截图准确率。
