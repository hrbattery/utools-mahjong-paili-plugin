# 手牌实验室 / fast-tenhou-paili

uTools 8 快速原型：截图导入 → 本地模板识牌 → 牌图/天凤牌串校正 → 本地数学进张分析。

## 运行

```sh
npm ci
npm test
npm run test:ui
npm run dev
```

`src/paili_engine.wasm` 已包含编译好的计算引擎，构建时内联到脚本以支持 uTools 的本地文件协议。普通前端开发不需要安装 Rust。

在 uTools「开发者工具」中新建本地插件，选择 `dist/plugin.json`，运行后搜索「牌理」。图片可从 uTools 主输入框粘贴进入，也可在插件内选图、粘贴、拖入或框选截图。此原型按 uTools 8 API 开发。

浏览器预览支持本地识牌、图片裁剪、文本/点选校正和完整本地计算。系统截图需要 uTools 宿主。在线 AI 识牌入口、模型选择和刷新已隐藏，启动时不查询模型列表；代码保留供后续恢复。

本地识牌使用 **雀魂标准、猫咪雀圣、飞鸟与鱼、天凤标准** 四套共 148 张模板，含各套三种赤五。在插件内粘贴图片，或从 uTools 主输入框粘贴图片进入插件后，会自动开始本地识牌。若识别不完整，可拖动框选自己的横向手牌（包含单独摸牌，排除副露），点击“应用裁剪”，再点击“本地识牌”重试；选图、拖入和框选截图仍使用此手动流程。连续换图只应用最新图片的识别结果，加载或识别期间编辑手牌会保留手动修改。识别自动比较四套模板，不上传截图。绿色框表示已匹配，橙色框和 `?` 表示待校正；不要用框的颜色代替核对牌数。当前不支持整桌自动定位、旋转牌、严重遮挡或过小牌面；边缘截断、强特效也可能漏牌，仍需人工确认。

手牌、点选牌表与进张结果使用 [lietxia/mahjong_graphic](https://github.com/lietxia/mahjong_graphic) 的 37 张 SVG 牌面，包含赤五和白板，随插件本地打包。鼠标悬停可查看牌名和编码，未知牌仍显示 `?` 供校正。素材保存在 `public/tiles/mahjong-graphic/`，固定版本与摘要见 `assets/mahjong-graphic/source.json`，许可随包附在 `public/licenses/`；显示素材不参与识别匹配。

原始素材在 `assets/<皮肤>/`，逐张原尺寸 PNG 和来源 / SHA-256 / 裁切坐标在 [assets/recognition-templates/](assets/recognition-templates/)。运行 `npm run templates:prepare` 可离线重新切分和生成 `src/generated/tile-templates.json`。运行时只内联图案与颜色特征，避免 uTools `file://` 下的资源请求；原始图集及样本截图不进入 `dist/`。本地匹配根据亮色牌面分割、图案相似度和颜色区分赤五，不按牌理补牌；分数不足或不同牌种得分过近时保留 `?`。

## 输入与计算约定

- 待切牌支持 `2/5/8/11/14` 张；待摸牌支持 `1/4/7/10/13` 张。
- 天凤牌串：`m` 万、`p` 筒、`s` 索、`z` 字，`1z–7z` 为东南西北白发中；`0m/0p/0s` 表示赤五。文本与点选编辑双向同步。空格和大写花色可接受。
- 默认开启“自动理牌”，识牌、点选校正和推演后自动整理；手动输入牌串在结束编辑后整理。关闭后保留当前及后续输入的牌序，重新开启会立即整理当前手牌。
- 只计算普通形、七对子、国士无双的向听数和降低向听数的有效进张，不计算收益、役、得分、振听、防守或同向听改良牌。
- 短手牌假定缺少的面子已固定；无需补齐即可算。已知吃碰杠可另填，例如 `123m 555p 7777z`。杠占一组面子、扣除四张牌；不区分明杠暗杠的得分语义。
- 未提供副露时只按手牌扣减，界面明确提示缺失组数；不是实际牌山剩余枚数。最多每种四张，红五与普通五合并计算。
- 采用 shanten-dp 的“可用牌约束”数学口径：输入已知副露后，不把已耗尽的牌视为未来可获得牌。该口径可能与平台对形式听牌的规则不同。
- 所有切牌候选均列出，先按切后向听数升序，再按进张枚数降序。赤五与普通五保持独立可选，但数学结果相同。
- 点击切牌，再点击有效牌可继续推演，支持撤销。模拟弃牌持续从可用牌中扣除。手动编辑、改副露或应用新识别会开始新分析。
- “天凤查看”仅传递当前手牌，不传副露、推演弃牌或可用牌约束；外部结果可能因此不同。
- 模型返回看不清的牌时保留 `?` 位置；所有牌位校正前不展示计算结果。输入非法时清除旧分析，防止误用。

## 复用边界

复用 tomohxx 的 **shanten-dp 0.3.2（MIT）**，保留版本锁与许可。自写标量 WebAssembly 桥接层，前端无服务器计算依赖。`pairi` 仓库在检视的提交 `6da8b46bc8b68fa936985dfb6f9bdce604c211e7` 未见许可证文件，因此没有复制其页面组件或图片资源。显示牌面来自上述 mahjong_graphic 素材库，使用其 M+ 字型许可。

来源与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

重新编译计算引擎需要 Rust（含 `wasm32-unknown-unknown` target）：

```sh
rustup target add wasm32-unknown-unknown
npm run build:engine
```

## 样本与验收

已准备 10 张天凤素材合成手牌、5 张公开雀魂对局图及其手牌裁剪，见 [samples/README.md](samples/README.md)。图片和标签保存在 `samples/private/`，可用 `npm run samples:tenhou`、`npm run samples:majsoul` 重新生成或下载。真实来源、标签与裁剪坐标保存在 `samples/majsoul-sources.json`；合成牌串保存在 `samples/tenhou-cases.json`。`samples/manifest.example.json` 用于继续标注自己的截图。

`npm test` 运行计算、解析与本地模板测试（四套各 37 种牌、缩放、抬牌、赤五/白板、未知图案及取消）。`npm run test:ui` 先构建，再使用 DOM 环境运行生产脚本，检查文本/点选同步、推演撤销、离线识牌及识别请求竞态。后者模拟 uTools 接口与图片解码，不等同于浏览器视觉验收或实际宿主调用。

运行 `npm run test:recognition-samples` 对本地样本进行逐张评估（需先准备 `samples/private/`）。2026-10-15 本地匹配结果：天凤同源合成图 **10/10 整手正确**；雀魂真实裁剪图 **3/5 整手正确**（开发集 2/3，初次验证集 1/2）。指示条遮挡和强特效样本失败，出现待校正及漏牌。两套主题皮肤目前只有素材变换测试，没有真实截图准确率证据。详见 [samples/README.md](samples/README.md)。uTools 导入运行和系统截图权限仍需实测。

新增真实截图可用 `npm run test:recognition-real` 复跑。透视校正、万子数字区加权和局部赤色特征加入后，同批整手正确由 **12/18 提升到 18/18**，221 张牌均与目视标签一致，原有相似度和候选分差门槛未降低。该批已用于开发，不代表独立验证准确率。

固定引擎后另取不同来源截图，以 `npm run test:recognition-holdout` 复跑：首次为 3 张无标签遮挡图中 **2 张整手正确**。随后修复浅粉色分割空档，并补偿高亮造成的字形对比度损失，H-M04 的二筒、五筒均正确识别，现为 **3/3 整手正确**；两批主组合计 **21/21、261 张牌全对**，接受门槛未降低。这一组已转为回归，不再是独立验证。另 1 张标签遮挡图仅作辅助。两张雀魂图来自同一作者；真实鼠标指针和主题牌面皮肤仍未验证。来源、标签和各阶段快照见 [samples/README.md](samples/README.md)。
