```sh
npm run samples:tenhou
npm run samples:majsoul
```

## 浅粉色二筒分割修复（2026-10-15）

H-M04 的二筒包含类似 RGB `(220, 181, 176)` 的浅粉色像素：最低通道 176 低于普通浅色门槛 180，色差 44 又低于原偏色门槛 48，因而被两条规则同时排除。连通区域断开后，牌框只剩 24 像素宽。本次补入亮度合格、红色占主导的浅粉色区间；保持其他颜色条件、同行尺寸检查、分类分数与分差门槛不变。浅黄色分析标签不纳入这个新增区间，避免标签与牌面粘连。

## 每张保留什么

1. 原始整桌 PNG，保留原始分辨率，不经聊天软件压缩。命名如 `majsoul-001-full.png`。
2. 一张手牌裁剪图，如 `majsoul-001-hand.png`，完整包含左侧手牌、最右侧摸牌和它们之间的空隙。不要切掉白板、牌边或最后一张摸牌。
3. 正确的天凤牌串，按图上从左到右标注；单独的摸牌也包含在内。红五记 0。不要把副露、牌河、宝牌指示牌写进手牌。
4. 能看清的副露单独标注，每组用空格分隔；未提供写空字符串，并用 `melds_complete: false` 明确区分未知与没有副露。

## 怎么评估

- 用前 7 张调提示词；后 3 张留作首次验证。以后扩大到每个平台至少 50 张，验证集不要参与调参。
- 同一原图与其裁剪版、相邻帧必须放在同一组，不能一张做调试、一张做验证。
- 保存所选模型、原始响应、识别耗时、是否成功、是否正确识别红五。
- 主要指标用“整手全部正确率”：牌数、每张牌和赤牌均正确才算成功；另记牌种多重集合准确率、逐张准确率、人工改牌次数、接口失败率和延迟中位数/P95。
- `null`/看不清计为待校正，不算自动识别成功。人工修正后的结果不能冒充原始识别结果。
- 20 张只用于发现明显问题，不足以承诺正式准确率。识牌链路未实测前，不能仅凭接口接通声称可用。
