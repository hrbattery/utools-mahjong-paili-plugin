# 怎样收集识牌样本

## 已准备的第一批样本

目前有 **10 张天凤合成手牌 + 5 张雀魂真实对局图**。图片与完整标签均在忽略 Git 的 `samples/private/` 中，不会进入插件 `dist/`。

| 目录 | 内容 | 用途 |
| --- | --- | --- |
| `private/tenhou/` | 37 种原始 GIF（含三种赤五）、10 张 PNG、`manifest.json` | 标准牌面识别、牌数与顺序、赤牌、短手牌的初步测试 |
| `private/majsoul/` | 5 张原图、5 张手牌 PNG 裁剪图、`manifest.json` | 检查整桌干扰、摸牌间隔、界面遮挡、特效和副露分离 |

使用界面的「选择图片」加载任一 PNG；在 uTools 中选视觉模型并点击「识别手牌」。天凤的 GIF 已拼成 PNG，无需修改现有导入格式。**只把图片发给模型，标签用于事后核对，不放入提示词。** 浏览器预览不能调用 uTools AI，当前没有真实模型准确率结果。

下载或重新生成：

```sh
npm run samples:tenhou
npm run samples:majsoul
```

脚本使用 Node 内置 TypeScript 执行（本地已用 Node 24 验证）、`curl` 和开发依赖 `sharp`。首次运行联网下载，后续使用本地原图缓存。改 [tenhou-cases.json](tenhou-cases.json) 可增加合成牌串；[majsoul-sources.json](majsoul-sources.json) 保存真实图的来源、裁剪坐标和目视标注。输出清单记录来源、原图摘要、逐张牌序、牌数与测试分组。

天凤样本覆盖 34 种普通牌与 3 种赤五；使用 [天凤提供的牌面素材](https://cdn.tenhou.net/2/t/2m.gif) 原尺寸直接拼接，没有生成或重画牌面。它们全部归入开发集，不能用于推断真实游戏截图准确率。

## 继续收集自己的截图

第一轮先收集雀魂、天凤各 **10 张**，不需要预先裁出每一张麻将牌。使用自己已有的牌谱回放，暂停到稳定画面再截屏即可。

## 每张保留什么

1. 原始整桌 PNG，保留原始分辨率，不经聊天软件压缩。命名如 `majsoul-001-full.png`。
2. 一张手牌裁剪图，如 `majsoul-001-hand.png`，完整包含左侧手牌、最右侧摸牌和它们之间的空隙。不要切掉白板、牌边或最后一张摸牌。
3. 正确的天凤牌串，按图上从左到右标注；单独的摸牌也包含在内。红五记 0。不要把副露、牌河、宝牌指示牌写进手牌。
4. 能看清的副露单独标注，每组用空格分隔；未提供写空字符串，并用 `melds_complete: false` 明确区分未知与没有副露。

将图放在 `samples/private/` 下，复制 `manifest.example.json` 到该目录并修改路径和牌串。这里的文件默认不提交 Git。

## 每个平台 10 张如何分配

| 样本 | 内容 |
| --- | --- |
| 1–4 | 普通 14 张，万筒索字混合；至少一张有单独摸牌间隔 |
| 5–6 | 红五、白板、发、中、多个重复牌；可与其他类别重叠 |
| 7–8 | 吃碰后 11 张或 8 张，截图中能同时看到固定副露 |
| 9 | 5 张或 2 张短手牌；找不到可先空缺，不用特意打出 |
| 10 | 日常较难截图，如小窗口、不同缩放或选中牌抬高 |

先用默认牌背/牌面即可。记录平台、客户端类型、窗口尺寸、系统/浏览器缩放、牌面皮肤。无需一次穷举全部组合。保留失败样本，不只挑清晰成功的图。

## 怎么评估

- 用前 7 张调提示词；后 3 张留作首次验证。以后扩大到每个平台至少 50 张，验证集不要参与调参。
- 同一原图与其裁剪版、相邻帧必须放在同一组，不能一张做调试、一张做验证。
- 保存所选模型、原始响应、识别耗时、是否成功、是否正确识别红五。
- 主要指标用“整手全部正确率”：牌数、每张牌和赤牌均正确才算成功；另记牌种多重集合准确率、逐张准确率、人工改牌次数、接口失败率和延迟中位数/P95。
- `null`/看不清计为待校正，不算自动识别成功。人工修正后的结果不能冒充原始识别结果。
- 20 张只用于发现明显问题，不足以承诺正式准确率。识牌链路未实测前，不能仅凭接口接通声称可用。
